# CS Booster — orientações do projeto

- Preserve a implementação própria do projeto; não adicione binários ou código extraído do aplicativo de referência.
- Repositório remoto: https://github.com/salazarantonio/cs-booster.
- O usuário autorizou atualizar este repositório conforme o projeto avança. Publique mudanças verificadas durante as sessões, sem prometer execução em segundo plano.
- Antes de publicar, confirme a visibilidade esperada e revise os arquivos que serão enviados. Não versionar data/, data-preview/, evidence/, release/, node_modules/, credenciais, logs ou backups do usuário.
- Execute npm test após alterações de lógica e documente limitações da validação da janela desktop.
- Nunca aplique ajustes reais ao computador apenas para testar a implementação. Use o registro simulado nos testes de escrita.
- Recursos sem executor devem permanecer identificados como pendentes na interface. Não exibir sucesso fictício.
- Alterações no registro devem usar lista de destinos autorizados, backup de existência/tipo/valor e leitura de verificação. Proteção efetiva da CPU não deve ser deduzida somente do registro.
